# SIN-T — модульный синтезатор (CLAP, C++)

Пет-проект: модульный программный синтезатор в формате CLAP на C++. Рабочий прототип готов, проект перешёл от разработки по этапам к постепенной доработке и полировке. Длинных планов нет: работаем короткими задачами по просьбе пользователя.

| Файл | Что там |
| --- | --- |
| `docs/TZ.md` | Техническое задание, ориентир по требованиям |
| `docs/DECISIONS.md` | Журнал решений D-001…: почему сделано так. Читать перед изменением затронутой подсистемы |
| `docs/BACKLOG.md` | Известные проблемы, что не подтверждено, что осталось |
| `docs/VERIFICATION.md` | Рецепты проверки: окно, Reaper, санитайзеры, мутации, `clap-validator` |

## Текущее состояние

Плагин работает в Reaper на Linux. Первоначальные этапы 0–7 завершены, 1 ноября пользователь проверил редактор в Reaper и сообщил, что всё нормально работает.

- **Звук:** двухуровневый граф (главный и подграф генератора на голос), осциллятор, фильтр, amp, ENV с кривыми, LFO, матрица модуляции, 8 макросов, педаль, правки схемы под звук без щелчков.
- **Редактор:** блоки с ручками, провода, вход в генератор, матрица, макросы, пресеты, масштаб экрана (D-063–D-069). Масштаба самого холста нет.
- **Хост:** автоматизация через постоянный список из 1032 слотов, запись движения ручки, сохранение в проект, файлы пресетов в `~/.local/share/SIN-T/presets/`.
- **Чего ещё нет:** Delay, сборки под Windows, отмены действий. Подробно в `docs/BACKLOG.md`.

Решения D-066–D-069 и кривые ENV (D-049) записаны со статусом `предложено`: пользователь их явно не подтверждал.

В `~/.clap/` лежит текущий `sint.clap` и старый прототип `sint-gui-prototype.clap`.

## Как работаем

- Пользователь — веб-разработчик (HTML, CSS, TS, Angular, React), в разработке UI для плагинов опыта нет. Новые для него темы объяснять простыми словами, с примерами и аналогиями из веба.
- Вопросы обсуждаем по одному, по порядку. К каждому — варианты с плюсами и минусами и своя рекомендация. Если пользователь не понял вопрос, сначала объяснить, не торопить с решением. Вопрос задаём, только если без ответа нельзя идти дальше.
- Решения пользователя важнее рекомендаций: они сразу записываются в `docs/DECISIONS.md`. Несогласованное записывается со статусом `предложено`. Журнал только для решений, а не для каждой мелкой правки.
- Проблему, которую можно решить позже, записать в `docs/BACKLOG.md` и идти дальше.
- Факты о чужих продуктах и API проверять по источникам или по заголовкам в `clap/`, не писать по памяти. Поведение Serum/Serum 2 в доступных источниках не подтверждено, на него не ссылаемся как на факт.
- Поведение существующего кода могло быть задумано намеренно, даже если оно расходится со стандартом и не прокомментировано. Перед изменением спрашивать пользователя и не называть его ошибкой без подтверждения. Если поведение намеренное, причину записать рядом с кодом и в журнале.
- `master` всегда рабочий, каждая задача идёт в короткой ветке от него и в конце вливается в `master` (D-070, D-080). Вне задачи коммиты только по просьбе пользователя. Push только с разрешения пользователя.
- После каждой влитой задачи увеличить счётчик в `docs/BACKLOG.md`, на 5 предложить задачу-уборку (D-074, D-080). Рефакторинг с функцией не смешиваем.
- Этот файл держим коротким: история проверок живёт в git, а подробности в `docs/`.

### Проверка по размеру правки

| Правка | Что нужно |
| --- | --- |
| Любая | `scripts/check.sh`: сборка, предупреждения как ошибки, все тесты, версии библиотек для flatpak-Reaper |
| Логика | Тест на новое поведение. Для сложного кода мутации |
| Внешний вид редактора | Набор кадров из `sint_editor_preview` (D-073), посмотреть глазами: тесты вид не проверяют |
| Потоки, аудиопуть | TSan и ASan, стресс-тест несколько раз, отрицательная проверка |
| Звук | Эталоны проходят без изменений. Намеренное изменение: `update_golden`, разница из отчёта, старые пресеты проверить отдельно (D-072, D-085) |
| Перед тем как сказать пользователю проверять | `cmake --install build --prefix ~/.clap`, зависимости в среде flatpak-Reaper |

Если меняется то, что видит DAW, проверить в Reaper. Что проверить не удалось, говорить прямо.

## Сборка

```sh
scripts/check.sh                                 # всё сразу, то же выполняет CI при push и PR в master (D-082)
cmake -S . -B build -G Ninja                     # настройка, зависимости скачиваются один раз
cmake --build build
ctest --test-dir build --output-on-failure       # sint_tests, sint_gui_tests, версии библиотек
cmake --install build --prefix ~/.clap
./build/sint_render out.wav --preset examples/two-saws.sintpreset --keys 45,57 --hold 3 --tail 0.1   # ещё --rate, --block
./build/sint_editor_preview out.ppm --open       # окно редактора и кадр, см. docs/VERIFICATION.md
cmake --build build --target update_golden       # только при намеренном изменении звука, см. docs/VERIFICATION.md
```

- g++, C++23 без расширений GNU, `-Wall -Wextra -Wpedantic`, сборка без предупреждений. Сборка по умолчанию — `RelWithDebInfo`.
- `-DSINT_BUILD_TESTS=OFF` без тестов, `-DSINT_BUILD_GUI=OFF` без редактора и его зависимостей, `-DSINT_WERROR=ON` предупреждения как ошибки.
- Новые `.cpp` добавляются в `CMakeLists.txt` явным списком.
- Зависимости закреплены версией и SHA256, редакторные описаны в `cmake/gui-dependencies.cmake`. Заголовки CLAP в `clap/` не редактировать.
- На машине: `git clone` с GitHub через прокси падает, `curl` и архивы работают; `dnf` не работает; `libstdc++-static`, `valgrind`, `Xvfb`, `xdotool`, `clap-validator` не установлены, `gdb` есть.

## Структура

- `engine/` — всё без DAW и окна. Одна сущность на папку.
  - Модель: `modelTypes`, `command`, `synthModel`, `preset`, `defaultPreset`, `sessionState`, `presetLibrary`, `slotTable` (со `SlotInbox` и `SlotOutbox`).
  - Описания: `parameterDescriptor`, `moduleDescriptor`, `moduleRegistry`, `builtinModules`, `moduleCatalog` (список всех модулей).
  - Исполнение: `engine`, `executionPlan`, `planExchange`, `modulationPlan`, `modulationCompiler`, `voicePool`, `generator`, `moduleProcessor`, `stubProcessor`.
  - Модули: `oscillator`, `filter`, `amp`, `env`, `lfo`, `macros`.
- `plugin/` — CLAP: `parameters.cpp` (значения от хоста), `editing.cpp` (правки со стороны плагина), `pluginEditorBackend` (плагин для редактора), `editor.cpp` (`clap.gui`, таймер), `noEditor.cpp` (сборки без окна).
- `gui/` — редактор: `editorView` (строит вид, мышь в команды), `editorDocument` (разметка и стили), `editorBackend` (контракт с плагином), `graphLayout`, `knob`, `wireLayer`, `wireGeometry`, `meshBuilder`, `rmlRuntime`, `pluginWindow`.
- `tests/` — doctest, `<тема>.test.cpp`. `modelFixture.h` — тестовые модули, `allocationCounter` — счётчик памяти в аудиопотоке. `parameters.test.cpp` — полный плагин через CLAP с записывающим хостом, `liveChanges.test.cpp` — правки под звук, `gui/editor.test.cpp` — настоящий RmlUi и плагин с пустой отрисовкой, мышь идёт через те же вызовы, что и в окне. `golden/` — эталоны звука.
- `tools/` — `offlineHost`, `wav`, `render`, `editorPreview`, `goldenScenarios` (сценарии эталонов), `updateGolden`. `examples/` — пресеты, проверяются тестом. `prototypes/gui-rmlui/` — старый прототип, нужен только ради `test_host`.
- `scripts/` — `check.sh` (полная проверка), `checkLibVersions.sh` (версии библиотек). `.github/workflows/check.yml` — CI.

Новый модуль: `engine/<name>/<name>Processor.{h,cpp}` с описанием, строка в `moduleCatalog`, `.cpp` в `CMakeLists.txt`. Ручки, порты и матрица появятся сами (ТЗ §12).

## Стиль кода

- Отступ 2 пробела, `#pragma once` в заголовках.
- Классы — `PascalCase`, методы и поля — `camelCase`, enum class — `UPPER_CASE` (`WAVE_TYPE::SAW`).
- Обращение к членам через `this->`.
- Комментарии на русском, к методам — `/** ... */`.
- Одна сущность — одна папка `<подсистема>/<name>/<name>.{h,cpp}`.

## Правила, которые нельзя нарушать

Подробности и причины в `docs/DECISIONS.md`.

**Потоки**
- В аудиопотоке нет блокировок, выделения и освобождения памяти (D-023, D-053). Тесты это считают.
- Модель живёт на главном потоке и меняется только через `SynthModel::apply` (D-030). Со стороны плагина единственный вход — `my_plug_apply_command` (D-067).
- Редактор не трогает DSP, говорит с плагином только через `EditorBackend` (D-015). Схема хранится только в модели, вид её догоняет (D-068).

**Совместимость проектов и пресетов**
- ID плагина `com.chillyswim.sin-t` не менять (D-022).
- Типы модулей и ключи параметров — постоянные строки. Диапазон параметра меняется только с миграцией (D-020, D-025). ID модулей не используются повторно (D-036).
- Новое поле в файле необязательно, а его значение по умолчанию даёт прежний звук: версия формата пока 1 (D-041, D-049, D-065).
- Пул слотов можно только увеличивать, номер слота — это `clap_id` (D-011).
- Неизвестный модуль становится заглушкой, его данные не теряются при пересохранении (D-021).

**Звук**
- Звук не зависит от размера блока DAW: сетка 32 сэмпла (D-008, D-052).
- Правки под звук плавные, ~10 мс, хвосты удаляемого обрываются затуханием (D-023, D-024, D-053).
- Циклы в аудиографе запрещены (D-007), в модуляции разрешены (D-010). Вложенных генераторов нет, правила зон — в D-004.
- Итог параметра = база + вклады, одно ограничение до 0..1, затем кривая (D-025). Аудио всегда стерео (D-026).

**Намеренные отступления, не «исправлять»**
- Note on с velocity 0 — отпускание (D-047).
- Модуль в имени параметра для хоста (D-057).
- Значение по умолчанию для хоста — значение при загрузке, а не из описания (D-061).

**Ловушки сборки и окружения**
- `std::format` нельзя: ему нужна libstdc++ новее, чем в среде flatpak-Reaper, и плагин там не загрузится (D-069). Числа в текст — через `std::to_chars`, он ещё и не зависит от локали.
- Хост может поменять локаль на весь процесс: в тексте стилей RmlUi нет дробных чисел (D-069).
- В `overflow: hidden` RmlUi не считает абсолютные блоки вложенного контейнера, холсту нужен `clip: always`. Для `dragdrop` нужен `drag: drag-drop`, а не `drag`.
- Открытый Reaper — это сеанс пользователя: не закрывать и не слать ему команды (`docs/VERIFICATION.md`).
