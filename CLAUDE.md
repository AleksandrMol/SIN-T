# SIN-T — модульный синтезатор (CLAP, C++)

Пет-проект: модульный программный синтезатор в формате CLAP на чистом C++.
Ориентир по требованиям — `docs/TZ.md` (ТЗ). Все архитектурные решения фиксируются в этом файле
(раздел «Журнал решений»). Если решение противоречит ТЗ — это явно отмечается здесь.

## Как работаем

- Пользователь — веб-разработчик (HTML, CSS, TS, Angular, React), в разработке UI для плагинов опыта нет. Новые для него темы объяснять простыми словами, с примерами и аналогиями из веба.
- Вопросы обсуждаем по одному, по порядку. К каждому — варианты с плюсами и минусами и своя рекомендация. Если пользователь не понял вопрос, сначала объяснить, не торопить с решением.
- Решения пользователя важнее рекомендаций: они фиксируются здесь сразу после подтверждения. Несогласованное записывается со статусом `предложено`.
- Факты о чужих продуктах и API проверять по источникам или по заголовкам в `clap/`, не писать по памяти. Поведение Serum/Serum 2 в доступных источниках не подтверждено, на него не ссылаемся как на факт.
- Коммиты: самостоятельно в конце каждого этапа, в остальное время только по просьбе пользователя. Рабочая ветка — `claude-branch`.
- Поведение существующего кода могло быть задумано намеренно, даже если оно расходится со стандартом и не прокомментировано. Перед изменением спрашивать пользователя и не называть его ошибкой без подтверждения. Пример — D-047. Если поведение намеренное, причину записать рядом с кодом и в журнале.
- Конец этапа: чистые сборки Release и Debug без предупреждений, все тесты, мутации нового кода, установка в `~/.clap`, проверка зависимостей в среде flatpak-Reaper, обновление этого файла, коммит.
- Мутации: нарочно ломать новый код по одному месту и смотреть, упадут ли тесты. Выжившую мутацию разобрать: дыра в тестах, лишний код или эквивалентная мутация. Ломать только копию проекта в папке для временных файлов, с `-DFETCHCONTENT_BASE_DIR` на копию `build/_deps` и `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`, чтобы не скачивать зависимости. Если исходники копируются поверх готовой сборки, обновить их даты через `touch`, иначе `ninja` оставит объектные файлы прошлой мутации. На этапах 1–6 такая проверка нашла настоящие дыры в тестах и лишний код.

## Сборка

```sh
cmake -S . -B build -G Ninja                     # настройка, зависимости скачиваются один раз
cmake --build build                              # build/sint.clap, build/sint_render, build/sint_tests
ctest --test-dir build --output-on-failure       # unit-тесты
cmake --install build --prefix ~/.clap           # установка в папку CLAP
./build/sint_render out.wav --keys 60,64,67 --hold 1 --tail 1.5   # офлайн-рендер нот (ещё --rate, --block)
./build/sint_render out.wav --preset examples/two-saws.sintpreset --keys 45,57 --hold 3 --tail 0.1   # рендер нот через граф из пресета
./build/sint_gui_tests                           # настоящий редактор и плагин с пустой отрисовкой, без окна
./build/sint_editor_preview out.ppm [--open] [--preset файл] [--scale 1.5] [--resize 1000x640] [--hold 5]   # окно редактора, кадр в PPM
cmake -S . -B build-tsan -G Ninja -DSINT_SANITIZER=thread && cmake --build build-tsan --target sint_tests   # отдельная сборка под ThreadSanitizer, также address
```

- Компилятор: g++, стандарт C++23 без расширений GNU, предупреждения `-Wall -Wextra -Wpedantic`. Сборка должна проходить без предупреждений.
- Новый код с потоками проверяется под ThreadSanitizer и AddressSanitizer, стресс-тест запускается не один раз. Зелёному прогону верить только после отрицательной проверки: намеренно внесённая гонка должна быть поймана.
- Сборка по умолчанию — `RelWithDebInfo`. Без тестов и без скачивания doctest: `-DSINT_BUILD_TESTS=OFF`. Без редактора и без скачивания RmlUi, pugl, FreeType и шрифта: `-DSINT_BUILD_GUI=OFF`, сборки с санитайзером так и работают. nlohmann/json нужен всегда.
- Зависимости редактора описаны в `cmake/gui-dependencies.cmake`. Они не попадают в `cmake --install` (`EXCLUDE_FROM_ALL`), собираются без отладочной информации и без наших предупреждений.
- Новые `.cpp` добавляются в `CMakeLists.txt` явным списком.
- Заголовки CLAP лежат в `clap/` (vendored, не редактировать).

Прототип GUI больше не развивается, редактор живёт в `gui/`. `test_host` прототипа по-прежнему полезен: он открывает и закрывает окна любого `.clap` и показывает расход памяти. Собирается отдельно (зависимости скачиваются с закреплённой версией и SHA256):

```sh
cmake -S prototypes/gui-rmlui -B build-proto -G Ninja
cmake --build build-proto
./build-proto/test_host build-proto/sint-gui-prototype.clap <папка для кадров> [число переоткрытий]
```

Особенности окружения:

- Система: Fedora 44, сессия Wayland. Reaper установлен через flatpak (`fm.reaper.Reaper`), видит домашнюю папку, работает через X11.
- Запуск в среде Reaper: `flatpak run --command=sh fm.reaper.Reaper -c '...'`. `/tmp` там свой, поэтому файлы для проверки класть в домашнюю папку.
- `git clone` с GitHub через прокси этой машины падал с `Proxy CONNECT aborted`, `curl` и загрузка архивов работают. Зависимости брать архивами по URL.
- `libstdc++-static` не установлен, поэтому `-static-libstdc++` сейчас не линкуется.
- `Xvfb`, `xdotool` не установлены. Окно редактора проверяется на настоящем дисплее: `sint_editor_preview` сохраняет кадр, Python читает PPM, а события мыши отправляются через `XSendEvent` в дочернее окно с классом `SintEditor`, как в `test_host`. pugl такие события принимает.
- `clap-validator` не установлен. Готовый архив есть в релизах `free-audio/clap-validator`, версия `0.4.1`, файл для `ubuntu-22.04`, контрольная сумма указана в API релизов. Значения параметров упавшего теста он пишет в `/run/user/1000/clap-validator/com.chillyswim.sin-t/`.
- `libasan` и `libtsan` не установлены, `dnf` падает на том же прокси. Обе библиотеки берутся без `sudo`: скачать RPM через `curl` с `dl.fedoraproject.org/pub/fedora/linux/updates/44/Everything/x86_64/Packages/l/`, проверить `rpm -K`, распаковать `rpm2cpio | cpio` во временную папку, рядом сделать символические ссылки `libtsan.so` и `libasan.so`, потому что системные файлы с этими именами ссылаются на отсутствующие пути. Затем настройка с `-DSINT_SANITIZER=thread` и `"-DCMAKE_EXE_LINKER_FLAGS=-L<папка> -Wl,-rpath,<папка>"`, цель `sint_tests`.
- `gdb` установлен, `valgrind` нет.
- У CLAP-плагинов в Reaper нет `vst_chunk`: `TrackFX_Get/SetNamedConfigParm` возвращают `false`. Состояние меняется через `SetTrackStateChunk`, блок `<STATE` — base64 от JSON состояния. Проект с другим пресетом собирается подстановкой этого блока.
- Reaper проверяется без участия пользователя, только пока он закрыт. Перед запуском проверить `flatpak ps`: открытый Reaper принадлежит пользователю, закрывать его и слать ему команды нельзя. `cmake --install` при открытом Reaper безопасен: файл заменяется новым, загруженная копия работает дальше и в `/proc/<pid>/maps` видна как `(deleted)`. Рендер: `flatpak run fm.reaper.Reaper -renderproject <проект.RPP>`, в проекте заполнить `RENDER_FILE` и `RENDER_FMT`. Живой звук: `flatpak run fm.reaper.Reaper -nosplash -new <скрипт.lua>`, нота идёт через `reaper.StuffMIDIMessage` на виртуальную клавиатуру (перед нотой дождаться ~1 с после включения записи на дорожке), уровень читается через `reaper.Track_GetPeakInfo`. Клик по пианоролу так не проверить. Запуск дописывает проекты в `reaper.ini`, файл нужно сохранить заранее и вернуть. Окно Reaper закрывается через `flatpak kill fm.reaper.Reaper`.
- Рендер проекта можно подготовить скриптом: `GetSetProjectInfo_String` с `RENDER_FILE`, `RENDER_PATTERN`, `RENDER_FORMAT` (`ZXZhdxgAAQ==` — WAV 24 бита) и `GetSetProjectInfo` с `RENDER_BOUNDSFLAG` = 1. Модуль `wave` такой WAV читает. Огибающая параметра хранится как `<PARMENV <слот>:<слот> ...>`. `GetFXEnvelope` не видит и не создаёт огибающие скрытых параметров.
- `sint_render` пишет WAV с плавающей точкой (формат 3). Модуль `wave` в Python такой файл не читает, данные разбирать вручную через `struct` и `array`.

## Структура

- `plugin/` — интеграция с CLAP: entry, factory, descriptor, методы плагина, расширения, события, process.
- `engine/` — простой DSP без графа: oscillator, filter.
- `engine/` — движок: moduleProcessor (контракт DSP-модуля), executionPlan, engine, stubProcessor, voicePool (учёт голосов), generator (генератор как модуль), moduleCatalog (список всех модулей). modulationPlan (типы модуляции и её расчёт в аудиопотоке), modulationCompiler (сборка модуляции в план), planExchange (передача планов между потоками и отложенное удаление). Модули: oscillator, filter, amp, env, lfo, у каждого `<name>Processor.{h,cpp}` с описанием. macros — только `macrosProcessor`, описание лежит в builtinModules.
- `engine/` — модель: parameterDescriptor, moduleDescriptor, moduleRegistry, builtinModules (выходы, генератор, макросы), modelTypes, command, synthModel, preset, defaultPreset, slotTable (таблица слотов хоста и `SlotInbox`), sessionState (состояние проекта), presetLibrary (файлы пресетов).
- `plugin/parameters.cpp` — расширение `clap.params` и путь значений от хоста к движку и модели.
- `plugin/editing.cpp` — правки со стороны плагина, `plugin/pluginEditorBackend.*` — редактор глазами плагина, `plugin/editor.cpp` — расширения `clap.gui` и `clap.timer-support`, `plugin/noEditor.cpp` — заглушка для сборок без окна.
- `gui/` — редактор, одна сущность на папку: `editorBackend` (контракт с плагином), `editorView` (строит вид, переводит мышь в команды), `editorDocument` (разметка и стили), `graphLayout` (авторасстановка), `knob`, `wireLayer`, `wireGeometry`, `meshBuilder` (своя отрисовка), `rmlRuntime` (общие ресурсы RmlUi), `pluginWindow` (pugl и OpenGL).
- `cmake/gui-dependencies.cmake` — зависимости редактора.
- `tools/` — утилиты (`midiToFreq`, консольный логгер), `offlineHost/` (запуск плагина без DAW), `wav/` (запись WAV), `render/` (консольный рендер), `editorPreview/` (окно редактора и кадр в файл), `glibcCompat.h` (D-019).
- `tests/` — unit-тесты на doctest, файлы `<тема>.test.cpp`. `modelFixture.h` — тестовые модули и заготовка модели, `allocationCounter` — счётчик выделений памяти. Тесты главного графа используют источник `test.tone` с параметром частоты (`engine.test.cpp`), ноты проверяются в `polyphony.test.cpp`, учёт голосов — в `voicePool.test.cpp`, события CLAP — в `clapPlugin.test.cpp`, ENV и LFO сами по себе — в `modulators.test.cpp`, маршруты и правила матрицы — в `modulation.test.cpp`: там источник `test.dc` выводит значение параметра прямо на выход, а `test.pass` — модулятор, выход которого равен параметру. Правки во время звука — в `liveChanges.test.cpp`: на постоянном сигнале щелчок виден как скачок между соседними сэмплами, там же стресс-тест двух потоков. Параметры через CLAP и правки редактора — в `parameters.test.cpp`: там хост, записывающий `rescan`, `clear`, `mark_dirty`, отправленные события и обращения к пресетам, и стресс-тесты; таблица слотов, `SlotOutbox` и состояние проекта — в `slotTable.test.cpp`. Редактор — в `gui/editor.test.cpp`, отдельный исполняемый файл: заготовка водит мышь через те же вызовы, что и окно, и проверяет модель. Авторасстановка и геометрия проводов — в `graphLayout.test.cpp`.
- `examples/` — примеры пресетов, проверяются тестом. `modulation-demo.sintpreset` показывает ENV, локальный и глобальный LFO: пока нет UI, матрицу можно услышать только так, через `sint_render --preset`.
- `docs/TZ.md` — техническое задание.
- `prototypes/gui-rmlui/` — прототип GUI, отдельный CLAP-плагин со своей CMake-сборкой; `test_host.cpp` проверяет его без DAW.

- Отступ 2 пробела, `#pragma once` в заголовках.
- Классы — `PascalCase`, методы и поля — `camelCase`, enum class — `UPPER_CASE` (`WAVE_TYPE::SAW`).
- Обращение к членам через `this->`.
- Комментарии на русском, к методам — `/** ... */`.
- Одна сущность — одна папка `engine/<name>/<name>.{h,cpp}`.

## Журнал решений

Формат: `D-<номер> [статус] — решение. Причина.` Статусы: `принято`, `предложено`, `отменено`.

- D-001 [принято] — Формат плагина: CLAP. Источник: ТЗ.
- D-002 [принято] — Язык: C++23 (компиляторы см. D-016). DSP-движок пишется без сторонних фреймворков. Источник: существующий код.
- D-003 [принято] — Подсистемы из ТЗ §2 (DSP, аудиограф, матрица модуляции, голоса, параметры, пресеты, UI, CLAP-интеграция) разделяются как отдельные модули кода с явными интерфейсами. Источник: ТЗ.

- D-004 [принято] — Модель полифонии: двухуровневый граф.
  - Главный граф — глобальная зона, модули существуют в одном экземпляре (эффекты, микшеры, глобальные модуляторы, макросы).
  - **Генератор** — модуль-контейнер главного графа с собственным пулом голосов (лимит полифонии, правила стилинга) и внутренним полифоническим подграфом. Подграф исполняется на каждый голос, у каждого голоса своё состояние модулей. Выход генератора — сумма голосов, в главном графе это обычный аудиовыход.
  - Внутренний и главный граф используют один и тот же механизм аудиографа и исполнения.
  - Модуль объявляет, допустим ли он в полифонической зоне (например, ревербератор — нет).
  - Вложенные генераторы запрещены: полифоническая зона одноуровневая.
  - Модуляция: голосовой модулятор генератора → параметр своего генератора — на каждый голос; → параметр другого генератора — запрещено; → глобальный параметр — значение последнего нажатого голоса этого генератора (собственное правило SIN-T; соответствие поведению Serum не подтверждено). Глобальный модулятор → любой параметр, одно значение для всех голосов.
  - Причина: ТЗ §5 (каждый источник управляет своими голосами, суммирование) + возможность поголосовой обработки (osc1+osc2 → фильтр на голос), которой нет при суммировании сразу после источника.

- D-005 [принято] — Общие голосовые модуляторы. Модулятор разделён на параметры (одни) и состояние (на голос).
  - Голосовой модулятор может быть локальным (внутри генератора, правила D-004) или общим (в главном графе).
  - Общий модулятор может модулировать параметры любого генератора: пул голосов генератора-потребителя выделяет каждому голосу слот состояния этого модулятора (при компиляции плана, не в аудиопотоке). Note On/Off и стилинг остаются у каждого генератора своими.
  - Для глобальных параметров у общего модулятора есть один глобальный экземпляр состояния, перезапускаемый каждой новой нотой («последняя нота»).
  - Причина: единое редактирование, например общего ADSR для нескольких генераторов, без дублирования.
- D-006 [принято, детали позже] — Завершение голоса: голос завершён, когда все голосовые огибающие, влияющие на него, находятся в IDLE; дополнительная страховка — тишина на выходе голоса дольше заданного порога. Детали уточняются при проектировании системы голосов.

- D-007 [принято] — Циклы в аудиографе в MVP запрещены: соединение, создающее цикл, отклоняется при проверке. Причина: простота и предсказуемость; автоматический разрыв цикла с задержкой в блок хоста сделал бы звук зависимым от размера буфера DAW (ТЗ §11.3).
- D-008 [принято] — Внутренний кусок обработки: движок режет блок хоста на куски не длиннее 32 сэмплов (константа компиляции), дополнительно по времени событий. Модуляция пересчитывается раз в кусок, внутри куска значения параметров интерполируются линейно. Причина: звук не зависит от буфера DAW, а CPU намного меньше посэмплового расчёта.
- D-009 [принято] — Порядок внутри куска: сначала модуляция, затем аудио. Источник модуляции, зависящий от аудио (например, envelope follower), видит аудио предыдущего куска. Причина: циклы между аудиографом и матрицей невозможны (ТЗ §7).
- D-010 [принято] — Циклы в модуляции разрешены. Модуляторы считаются в порядке зависимостей; маршрут, замыкающий цикл, берёт значение источника с предыдущего шага. Замыкающий маршрут выбирается детерминированно, по порядку создания маршрутов, чтобы пресет звучал одинаково при каждой загрузке.
- D-011 [принято] — Экспорт параметров в хост: фиксированный список из 8 макросов (всегда видны) и пула из 1024 слотов (скрыты, пока не заняты). Количество параметров для хоста никогда не меняется.
  - Причина: добавление и удаление параметров в CLAP требует `RESCAN_ALL` на деактивированном плагине, то есть перезапуска и обрыва звука при каждом изменении графа (нарушило бы ТЗ §4.4). Имя и `is_hidden` меняются через `RESCAN_INFO` сразу, без перезапуска.
  - Параметр занимает слот автоматически при создании модуля; при удалении модуля слот скрывается и освобождается, автоматизация сбрасывается через `clear`.
  - Все слоты имеют диапазон 0..1 и не помечены как stepped; реальные единицы и текст даёт сам параметр (`value_to_text`).
  - Таблица «слот → модуль и параметр» хранится в состоянии. Модуль имеет постоянный ID, параметр — постоянный ключ.
  - Макрос — обычный источник модуляции в матрице, значение которого задаёт хост.
  - Параметры генератора занимают по одному слоту независимо от числа голосов.
  - При нехватке слотов параметр работает, но не экспортируется, UI это показывает; обходной путь — макрос.
  - Пул можно только увеличивать: уменьшение сломает существующие проекты.
  - Поведение скрытых параметров и обновления имён нужно проверить в DAW на этапе CLAP-интеграции (ТЗ §10). Reaper 7.83: скрытие, имена и показ через `RESCAN_INFO` работают на лету, значения скрытых параметров хост всё равно присылает, `clear` не работает (см. «Известные проблемы»). FL Studio не проверялся.
- D-012 [принято] — Целевые платформы: Linux и Windows обязательны, macOS опционально. Платформозависимый код изолируется, чтобы macOS можно было добавить без переработки.
- D-013 [принято] — GUI без браузерного движка: WebView (WebView2, WebKitGTK, CEF) не используется. Причина: расход памяти на каждый экземпляр плагина.
- D-014 [принято для Linux: прототип `prototypes/gui-rmlui/` проверен пользователем в Reaper, на этой основе сделан редактор; на Windows и в FL Studio не проверялся] — GUI на RmlUi (разметка и стили, похожие на HTML/CSS, логика на C++) и pugl (окно, встраивание в окно хоста), отрисовка через OpenGL. Отклонение от «без фреймворков»: библиотеки допустимы для окна и отрисовки UI, DSP-движок по-прежнему без них (D-002).
- D-015 [принято] — UI общается с движком только сообщениями: команды и снимки состояния, без прямого доступа к DSP. Причина: UI можно заменить, не трогая движок.
- D-016 [принято] — Сборка: CMake вместо Makefile (переход выполняется отдельным шагом). Компиляторы: g++ на Linux, MSVC на Windows. Это уточняет D-002. Зависимости (RmlUi, pugl, FreeType) линкуются статически: пользователь получает один файл `.clap`.
- D-017 [принято] — Unit-тесты: doctest. Движок тестируется без DAW и без GUI.
- D-018 [принято] — Проверка в DAW: Reaper на Linux, FL Studio на Windows; другие DAW позже.
- D-019 [предложено] — Плагин должен загружаться в flatpak-Reaper, где glibc старше системной. Сейчас это решает привязка символов libm в `glibc_compat.h` (прототип). Для релизов нужна сборка в среде со старой glibc.
- D-020 [принято] — Формат пресетов и состояния: JSON, разбор через nlohmann/json, только на главном потоке.
  - Состояние проекта DAW = пресет + данные, не влияющие на звук (таблица слотов D-011, имя загруженного пресета). Положение блоков лежит в пресете (D-065).
  - Типы модулей и ключи параметров — постоянные строки, не индексы. Параметр, которого нет в пресете, получает значение по умолчанию.
  - Версии: `version` формата файла и `typeVersion` у каждого модуля. Миграции — цепочка шагов v1→v2→v3.
  - Загрузка: файл целиком разбирается и проверяется во временной модели и только потом подменяет текущую. При ошибке текущее состояние не меняется.
  - Пресет по умолчанию встроен в бинарник. Файлы: `~/.local/share/SIN-T/presets/` на Linux, `%APPDATA%\SIN-T\presets\` на Windows, расширение `.sintpreset`.
- D-021 [принято] — Неизвестный модуль при загрузке пресета заменяется заглушкой: сигнал проходит сквозь неё к следующему модулю цепочки, исходные данные сохраняются и не теряются при пересохранении.
  - Порты заглушки восстанавливаются по сохранённым соединениям: сумма входов идёт на каждый выход. Без входов заглушка молчит (например, неизвестный источник звука).
  - Маршрут от неизвестного источника модуляции даёт 0; маршруты на её параметры сохраняются, но не действуют.
- D-022 [принято] — Постоянный ID плагина: `com.chillyswim.sin-t`. Менять нельзя: DAW находит плагин в сохранённых проектах по этой строке. Проекты со старым ID-заглушкой плагин не откроют.
- D-023 [принято] — Изменение графа во время воспроизведения (ТЗ §4.4, §11.2).
  - Главный поток меняет модель, выделяет память и собирает неизменяемый план исполнения (порядок модулей, буферы, маршруты модуляции). План публикуется атомарной подменой указателя, аудиопоток забирает его в начале блока.
  - В аудиопотоке нет блокировок, выделения и освобождения памяти. Старые планы и удалённые объекты возвращаются главному потоку через очередь без блокировок и освобождаются там.
  - Состояние модулей хранится отдельно от плана, поэтому подмена не сбрасывает фазы, огибающие и линии задержки.
  - Если аудиопоток ещё не забрал план, более новый заменяет его. Изменение параметров план не пересобирает. Когда обработка звука не идёт, изменения применяются напрямую.
  - Изменения плавные, ~10 мс (константа): новое нарастает с нуля; удаление идёт в два шага — план с затуханием, затем план без элемента и освобождение памяти. В модели и UI элемент исчезает сразу.
- D-024 [принято] — Хвосты эффектов при удалении всегда обрываются с затуханием ~10 мс. Режима «дозвучать» нет. Причина: удалённый модуль не должен продолжать звучать (ТЗ §4.4).
- D-025 [принято] — Расчёт параметров (ТЗ §6.4).
  - Итог = база (0..1) + сумма вкладов маршрутов (глубина × значение источника), одно ограничение до 0..1 после суммирования, затем кривая параметра в реальные единицы.
  - Модуль объявляет у параметра: ключ, имя, диапазон, значение по умолчанию, кривую (линейная, логарифмическая), единицы, признаки «ступенчатый» и «модулируемый».
  - Источник объявляет полярность выхода: ENV 0..1, LFO −1..1. Глубина маршрута −1..1. Контракт маршрута допускает дополнительные настройки в будущем.
  - Глобальные вклады считаются один раз, голосовые — на каждый голос: итог голоса = база + глобальные + вклады голоса. Текущий класс `Parameter` разделяется на описание и значения.
  - Ступенчатые параметры модулируются, если модуль это разрешил: итог округляется и меняется на границе куска, без интерполяции. Тип волны осциллятора модулируемый.
  - Изменение базового значения сглаживается ~10 мс. Модуляция дополнительно не сглаживается: хватает интерполяции внутри куска (D-008).
  - Модуль получает значения в реальных единицах на концах куска и линейно интерполирует между ними.
  - В пресете хранятся реальные единицы (`"cutoff": 1200`), в слотах хоста — 0..1. Менять диапазоны параметров после релиза можно только с миграцией.
- D-026 [принято] — Формат аудиосигнала: каждое аудиосоединение всегда двухканальное (стерео). Причина: один формат всех портов, без преобразований моно ↔ стерео. Цена: моносигнал считается дважды.
- D-027 [принято] — Нотные данные в MVP.
  - Velocity — источник модуляции в матрице.
  - Pitch bend — глобальное значение, влияет на высоту всех голосов; диапазон — настройка генератора.
  - Ноты адресуются по `note_id` из CLAP, чтобы позже добавить MPE и note expressions. Сами они после MVP.
- D-028 [принято] — Синхронизация LFO с темпом входит в MVP: темп берётся из транспорта в `process`.
- D-029 [принято] — Unison после MVP. Контракт генератора не должен этому мешать: один голос сможет содержать несколько экземпляров подграфа.
- D-030 [принято] — Все изменения модели проходят через команды (вместе с D-015). Сам undo/redo реализуется позже, но обходных путей мимо команд быть не должно: иначе редактор придётся переписывать.
- D-031 [принято] — Дополнительный эффект MVP (ТЗ §13): delay. Причина: прост и проверяет работу с хвостами.
- D-032 [принято] — Офлайн-рендер и тесты звука работают с плагином через публичный интерфейс CLAP (`clap_entry`, фабрика, `process`), а не вызывают движок напрямую. Причина: переработка движка на этапах 2–3 не затронет их, заодно проверяется слой CLAP.
- D-033 [принято] — Описание модуля (`ModuleDescriptor`: порты, параметры, допуск в полифоническую зону) лежит рядом с его DSP-кодом в `engine/<name>/`. Модель зависит только от типа описания и получает конкретные описания через реестр типов (`ModuleRegistry`), поэтому от DSP не зависит. Тесты модели используют тестовые описания. Причина: новый модуль добавляется в одном месте (ТЗ §3.2, §12), параметры описания и DSP не расходятся.
- D-034 [принято] — Выход графа — обычный модуль: `output` в главном графе и `voiceOutput` в подграфе генератора, как `AudioContext.destination` в Web Audio. Создаётся автоматически, в графе ровно один, вручную его нельзя создать или удалить. Причина: соединения, проверка циклов, сохранение и порядок исполнения работают без особых случаев, главный граф и подграф используют один механизм (D-004).
- D-035 [принято] — К одному входу можно подключить несколько проводов, сигналы суммируются, как в Web Audio. Повторный провод между теми же двумя портами отклоняется. Причина: объединение работает без отдельного модуля-микшера, которого нет в составе MVP (ТЗ §13). Громкость отдельного провода задаётся модулем с параметром уровня.
- D-036 [принято] — Устройство модели. Хранилище плоское, как нормализованный store в Redux: все модули в одной таблице по ID, модуль подграфа отличается полем `owner`. Изменение — только `SynthModel::apply(Command)`, команды — данные. Значения параметров хранятся в реальных единицах, ID не используются повторно, счётчик ID сохраняется в файле. Причина: один код для всех графов, модель копируется целиком (D-020).
- D-037 [принято] — Загрузка пресета собирает новую модель, соединения и маршруты проходят через обычные команды, поэтому файл проверяется теми же правилами. Прямое восстановление модулей с их ID доступно только `loadModel`. Модуль более новой версии (`typeVersion` выше известной) считается заглушкой D-021, файл более новой версии формата не открывается. Причина: данные не теряются, правила проверки не дублируются. Исключение: генератор и выходы заглушкой быть не могут, такой файл отклоняется.
- D-038 [принято] — Устройство движка. DSP-часть модуля — `ModuleProcessor`, фабрика указана в описании, значения параметров приходят как `ParameterRamp` (D-025). Куски идут по общей сетке 32 сэмпла от начала работы, а не от начала блока, иначе границы кусков зависели бы от буфера DAW (D-008). Исполняются только модули, от которых сигнал доходит до выхода. Модуль без DSP-реализации ведёт себя как заглушка D-021: так работает и генератор до этапа 3. Новые модули оборачивают старые `Oscillator` и `Filter`, поэтому `Voice` продолжает работать. Параметр осциллятора `frequency` временный: на этапе 3 высоту задаёт нота.
- D-039 [отменено: старый синтезатор удалён на этапе 3, правило про неактивный плагин снято на этапе 5] — Новый движок работает рядом со старым. Граф попадает в плагин через расширение CLAP `state`, как при открытии проекта, поэтому рендер графа идёт через CLAP (D-032). Без графа звучит старый синтезатор, ноты в Reaper работают. Новый граф принимается только на неактивном плагине: подмены плана во время звука нет до этапа 5. Состояние, совпадающее с текущим, принимается всегда. Причина: нот в графе нет до этапа 3, при этом ничего не ломается.
- D-040 [принято] — Отключение модуля (ТЗ §3.3): отключённый модуль пропускает сумму входов на каждый выход, как заглушка D-021. Источник без входов молчит, выход модуляции отключённого модулятора даёт 0. Это команда (`SetModuleEnabled`), значение сохраняется в пресете, выход графа отключить нельзя. Причина: цепочка не рвётся, так работает привычный bypass. Цена: модуль, вносящий задержку сигнала, при отключении её теряет; таких модулей пока нет.
- D-041 [принято] — Детали отключения. Отключённый модуль не исполняется, его состояние замирает и продолжается после включения. Соединения, маршруты и параметры сохраняются. Заглушку отключить нельзя: она и так пропускает сигнал, а её исходные данные не должны меняться. Поле `enabled` пишется в пресет только со значением `false`, поэтому версия формата остаётся 1 и старые файлы читаются как есть.

- D-042 [принято] — Перехват голоса при занятом пуле: сначала отпущенный голос (идёт релиз), среди них самый старый; если таких нет, самый старый из удерживаемых. Забранный голос затихает быстро и плавно. Причина: удерживаемый аккорд не рвётся из-за хвостов, выбор не зависит от звука, поэтому детерминирован.
- D-043 [принято] — Громкость голоса. ENV остаётся модулятором (ТЗ §3.1), громкость задаёт отдельный модуль `amp` с параметрами `gain` и чувствительности к velocity, огибающая подключается маршрутом ENV → `amp.gain`. Чувствительность вынесена в `amp`, потому что вклады модуляции складываются (D-025), а громкость — произведение ENV и velocity. ENV, поголосовые маршруты и завершение голоса по огибающим переносятся на этап 4; `amp` делается на этапе 3. Старый синтезатор удаляется на этапе 3. Голос без ENV после отпускания ноты затихает за ~10 мс и освобождается. Причина: этап 3 не разрастается, на этапе 4 ничего не переделывается.
- D-044 [принято] — Устройство голосов. `GeneratorProcessor` — обычный модуль главного графа, он держит `VoicePool` и состояния подграфа на каждый слот голоса, поэтому они не зависят от плана (D-023). План подграфа приходит с куском и собирается тем же кодом, что и главный граф; буферы у голосов общие, потому что голоса считаются по очереди. Слотов вдвое больше лимита: новая нота занимает свободный слот, пока забранный голос затихает. Если за время затухания нот пришло больше лимита, забирается самое старое затухание, и это может щёлкнуть. Затухание линейное, 10 мс. Новая нота начинается с `reset()` всех модулей голоса, поэтому в контракте `ModuleProcessor` появился `reset`. Ноты получают только включённые генераторы, от которых сигнал доходит до выхода. Причина: один механизм исполнения (D-004), нет выделения памяти в аудиопотоке, забранный голос не щёлкает.
- D-045 [принято] — Высота ноты. Параметр осциллятора `frequency` заменён на `coarse` (±48 полутонов, ступенчатый) и `fine` (±100 центов). Высоту и velocity модули получают через `VoiceContext`. Осциллятор вне генератора допустим и звучит на A4 с velocity 1, нот не слышит. Частота ограничена 0,49 частоты дискретизации, иначе шаг фазы становится некорректным.
- D-046 [принято] — События. Нотный порт объявляет диалекты `CLAP` и `MIDI`: pitch bend в CLAP приходит только сырым MIDI, ноты в таком виде тоже обрабатываются. `reset` и каждая активация освобождают все голоса. Пресет по умолчанию собирается командами. Состояние модуля пересоздаётся, если под тем же ID оказался модуль другого типа: это возможно при смене пресета. Старый процессор уходит через `bury`, а не удаляется сразу: на неактивном плагине прошлый план ещё ссылается на него (ошибка найдена на этапе 7 тестом редактора).
- D-047 [принято] — Note on с нулевой velocity всегда считается отпусканием. Это сознательное отступление от CLAP, где такая нота допустима и не должна считаться note off. Причина: старые синтезаторы, подключённые как MIDI-клавиатуры, отпускают клавишу через note on с velocity 0, а хост может передать это плагину как `CLAP_EVENT_NOTE_ON`; по правилу CLAP такие ноты зависают. Голос ищется по порту, каналу и клавише без `note_id`: хост мог выдать событию новый ID. Цена: нота с velocity 0 не звучит, а при двух голосах на одной клавише отпускаются оба. Отвергнуто: отпускать только при удерживаемой клавише, иначе нота снова зависает, если голос уже забрали.
- D-048 [принято] — Вид модулятора определяется его типом и расположением, отдельной настройки нет. ENV всегда голосовой: внутри генератора локальный, в главном графе общий (D-005). LFO в главном графе всегда глобальный, с одной фазой на всех. LFO внутри генератора свой на каждый голос и перезапускается с нотой. Причина: новых настроек нет, в движке меньше сочетаний. Цена: для LFO с отдельной фазой на ноту в двух генераторах нужно ставить по LFO в каждый. Настройку «глобальный / на голос» можно добавить позже: старые пресеты получат значение «глобальный».
- D-049 [принято] — ENV — это ADSR, все стадии линейные. Attack, Decay и Release 1 мс..10 с (логарифмическая кривая параметра, поэтому минимум не 0), Sustain 0..1. По умолчанию 5 мс, 300 мс, 0,7 и 200 мс; значения предварительные. Настройка кривой каждой стадии добавлена на этапе 7 как новые параметры `attackCurve`, `decayCurve`, `releaseCurve`, −1..1, по умолчанию 0: это линейная стадия, поэтому старые пресеты звучат так же, вплоть до бита. Сама огибающая идёт линейно, кривая меняет только выход (степень `4^-кривая`), поэтому время стадии от неё не зависит. Значение больше нуля проходит стадию быстрее в начале, это ближе к экспоненциальному спаду. Спад начинается с услышанного уровня, поэтому отпускание на изогнутой стадии не даёт скачка. Статус кривых: `предложено`.
- D-050 [принято] — LFO: Wave (синус, треугольник, пила, меандр; по умолчанию синус), Rate 0,01..50 Гц (2 Гц), Sync выкл/вкл (выкл), Division 1/1..1/32 с триолями и нотами с точкой (1/4). При Sync скорость задают Division и темп; если хост темп не сообщает, берётся 120 BPM. Синхронизация только по темпу, это уточняет D-028: фаза идёт сама и к позиции в проекте не привязана. Причина: простой код, запуск и остановка транспорта ничего не дёргают. Цена: глобальный LFO не попадает в такты, а при каждом запуске проекта может оказаться в другой фазе. Привязку к тактам можно добавить позже как новую настройку.
- D-051 [принято] — Завершение голоса, уточняет D-006. Голос держат ENV, от которых цепочка маршрутов доходит до параметра модуля, через который проходит звук этого голоса: напрямую или через другой модулятор. Общий ENV считается так же, отключённый и ENV без маршрутов не считаются. Генератор без таких ENV после отпускания затихает за 10 мс. Голос всегда заканчивается затуханием 10 мс: ENV мог стоять не на громкости, и без затухания был бы щелчок. Страховка: отпущенный голос тише −100 дБ дольше 0,5 с освобождается; удерживаемые она не трогает, потому что LFO мог заглушить ноту временно. Причина: модуль без маршрутов ни на что не влияет, `amp` не становится особым модулем (ТЗ §3.2). Цена: ENV на параметре, не влияющем на громкость, держит тихий голос до страховки.
- D-052 [принято] — Устройство матрицы модуляции.
  - Модуляция считается раз на шаг сетки 32 сэмпла, сразу на весь шаг и перед звуком. Значение параметра на сэмпле зависит только от положения сэмпла на сетке (`ProcessChunk::at`), поэтому звук не зависит от буфера DAW вплоть до бита. Отвергнуто: резать значения по границам блока, разница округления накапливалась бы в состоянии модулей.
  - Шаг идёт так: глобальные модуляторы, голоса генераторов, параметры главного графа. Поэтому голос видит глобальный модулятор сразу, глобальный параметр видит голос сразу, а глобальный модулятор видит голос с задержкой на шаг. Это уточняет D-010: цикл через границу зон разрывается здесь, а не по порядку создания маршрутов.
  - Нота в середине шага начинается в свой сэмпл: модуляторы выдают начальное значение (`frames = 0`), затем доходят до границы сетки укороченным участком. Отпускание и завершение голоса применяются на границе сетки.
  - «Последний голос» (D-004) — самый поздний из ещё звучащих, поэтому после конца последней ноты значение берёт предыдущая. Когда голосов нет, значение равно 0.
  - Глобальный экземпляр общего ENV (D-005) перезапускается с нуля на ближайшей границе сетки, отпускается отпусканием или choke последней ноты.
  - Velocity — выход модуляции самого генератора (`velocity`), зона источника определяется как у цели, поэтому правила D-004 действуют и для него.
  - Базовое значение одно на модуль и хранится отдельно от голосов, `Engine::setParameter` сглаживает его линейно в нормированном виде. Ступенчатая база меняется сразу на границе шага. `applyModel` принимает значения без сглаживания.
  - Причина: все правила одним кодом для всех зон, в аудиопотоке только готовые указатели, без поиска и выделения памяти.

- D-053 [принято] — Устройство подмены плана, уточняет D-023.
  - План лежит в почтовом ящике (`PlanExchange`, один атомарный указатель) и забирается на границе сетки 32 сэмпла, а не в начале блока: так значения шага всегда считаны одним планом. Отвергнуто: забирать посреди шага, тогда новому плану пришлось бы доигрывать чужой шаг.
  - Обратной очереди нет. У планов и удалённых объектов есть номер поколения, аудиопоток сообщает одним атомарным числом самое старое поколение, которое ещё читает, а всё, что старше, удаляет главный поток. Результат тот же, что у очереди из D-023, но её нельзя переполнить.
  - Одновременно идёт один переход. Пока он длится (15 шагов сетки при 48 кГц, ~10 мс), правки копятся и применяются вместе следующим переходом. Поэтому значения затухания живут в самом плане и всегда начинаются с известных чисел, а уходящих элементов не может быть больше одного поколения. Отвергнуто: постоянные объекты затухания, чтобы правка могла начаться посреди чужой: сложнее, а при правках чаще 10 мс уходящие элементы копились бы без предела. Цена: правка в момент перехода ждёт его конца и вызова `on_main_thread`.
  - Переход — это схема из старой и новой моделей (`mergeModels`). Старые провода затухают, новые нарастают, отключаемый модуль смешивается с суммой входов, глубина маршрута меняется линейно. Затем план без уходящего, в котором нет ни одного значения перехода: вне переходов звук считается так же, как до этапа 5.
  - Провод, который образовал бы цикл с ещё затухающим, ждёт следующего перехода (D-007). Цена: между двумя схемами короткий провал.
  - Параметры идут мимо плана: у базового значения есть атомарное поле, а аудиопоток читает его на границе сетки, если поднят флаг. Важно только последнее значение, поэтому очереди и её переполнения нет. `polyphony` идёт через план, потому что голосам может понадобиться память.
  - Новый план один раз пересчитывает значения всех параметров: он мог начать исполнять модуль, значения которого давно никто не считал.
  - Генератор, вышедший из плана (удалён, отключён, отсоединён от выхода), освобождает все голоса: он уже затих вместе с проводом, а note off больше не получит. Новый генератор получает только следующие ноты (ТЗ §5.4).
  - Лимит голосов меняется вместе с планом, лишние затихают в порядке D-042. Память голосов только растёт, пока модуль жив. Новый модуль в звучащем голосе начинает с чистого состояния: огибающая начинает атаку.
  - Причина: нет блокировок и выделения памяти в аудиопотоке, вся логика переходов проверяется одним кодом.
- D-054 [принято] — Замена всего состояния: пресет и `state.load` на работающем плагине. ID модулей в другом пресете могут совпасть, поэтому состояние создаётся целиком заново и не пересекается со старым. Оба плана звучат одновременно, переход 10 мс, голоса старого заканчиваются, новые ноты сразу идут в новый. Если на выходе тишина, план меняется сразу: иначе нота в начале рендера DAW прозвучала бы мягче. Модель меняется сразу, поэтому хост может тут же сохранить состояние. Цена: 10 мс двойной нагрузки на CPU. Отвергнуто: заглушить, подменить, поднять громкость: нота в эти 10 мс терялась бы, а в рендере DAW первая нота проекта попала бы в старый план.

- D-055 [принято] — Макросы как модуль, уточняет D-011. Встроенный модуль `macros` с постоянным ID 0 есть в любой модели, его нельзя создать, удалить и отключить. У него 8 параметров 0..1 и 8 выходов модуляции, выход равен параметру. Зона глобальная, как у глобального LFO, поэтому правила D-004 действуют без новых случаев. Параметр не модулируется. Положение макроса влияет на звук и хранится в пресете; несдвинутые макросы в файл не пишутся, поэтому версия формата осталась 1 и старые файлы читаются как есть. Причина: сглаживание, слоты, пресеты и матрица работают без отдельного кода. ID 0 не пересекается со старыми файлами: обычные ID начинаются с 1.
- D-056 [принято] — Значение от хоста идёт двумя путями. Сразу в звук: `Engine::setSlot` в аудиопотоке, адреса слотов лежат в плане, сглаживание D-025. С задержкой в модель: ячейка на слот в `SlotInbox`, главный поток забирает их в `on_main_thread`, `get_value` и `state.save`, поэтому хост всегда видит то, что прислал. Модель обновляется командой (D-030), движку только сообщается через `acknowledgeParameter`: иначе следующий `applyModel` принял бы значение за правку и вернул бы вдогонку устаревшее. Параметр с `isStructural` (сейчас `polyphony`) идёт только через модель и план, поэтому при рендере без главного потока он применится позже. Вне работы звука `flush` применяет значения сразу. Значения, не дошедшие до модели к моменту замены состояния, сначала записываются в старую модель и в новую не попадают. Причина: автоматизация не зависит от главного потока, который в рендере DAW может не вызываться, а хост читает значения без блокировок.
- D-057 [принято] — Имя параметра для хоста содержит модуль: `G1 Filter 1 Cutoff`, `G1 Polyphony`, `LFO 1 Rate`, `Macro 1`. Путь `module` тоже заполнен: `Generator 1/Filter 1`. Заголовок CLAP советует не повторять модуль в имени, но `TrackFX_GetParamName` в Reaper 7.83 отдаёт только имя, без модуля, а у огибающей из пути берётся только последняя часть, поэтому два осциллятора в списке выглядели бы одинаково. Номера считаются среди модулей того же типа в одном графе, после удаления сдвигаются, хост узнаёт об этом через `RESCAN_INFO`. Цена: имена длиннее. Имена нигде не сохраняются, поменять их можно в любой момент.
- D-058 [принято] — Педаль sustain (CC64) и паника. Значение от 64 нажимает педаль, состояние на канал одно на движок. Отпущенная клавиша под педалью остаётся удерживаемым голосом, отпускание педали отпускает только такие голоса. Глобальный экземпляр общего ENV ведёт себя так же. При перехвате D-042 порядок: отпущенный, под педалью, под пальцами. CC123 отпускает ноты и педаль канала, CC120 заглушает их за 10 мс. Reaper шлёт педаль сырым MIDI, даже когда ноты идут событиями CLAP, и сам присылает CC64 = 0 при остановке и перемотке. `reset` педаль снимает.
- D-059 [принято] — Пресеты в файлах и состояние проекта, уточняет D-020.
  - `PresetLibrary`: список, чтение и запись в папке пресетов. Создание не перезаписывает существующий файл, обновление идёт отдельным режимом, запись атомарная через переименование. Папка строится от `HOME`, а не от `XDG_DATA_HOME`: в flatpak XDG указывает внутрь песочницы, и у каждого хоста были бы свои пресеты.
  - Плагин принимает пресет через `clap.preset-load` (только файлы). Сохранение и список в DAW пока недоступны: их кнопки появятся на этапе 7.
  - Фабрика `clap.preset-discovery-factory` не сделана. Reaper при сканировании её не запрашивает, поэтому пока её нечем проверить. Строка с её ID в бинарнике Reaper есть, запрос при открытии списка пресетов в окне FX не проверялся. Без фабрики хост не узнает пути к пресетам, так что `from_location` сейчас вызывается только тестами.
  - Состояние проекта — JSON пресета плюс раздел `session`: имя пресета и занятые слоты пула. Поэтому пресет загружается как состояние, а файл без раздела (проект этапов 1–5) получает слоты заново.
  - Запись таблицы содержит ID, тип и ключ параметра. При смене пресета слот сохраняется, если в новом пресете есть модуль с тем же ID и типом: повторная загрузка пресета не теряет автоматизацию. Остальным слотам вызывается `clear`.
- D-060 [принято] — `CLAP_EVENT_NOTE_END` не отправляется до MPE и note expressions (D-027). Он нужен хосту, который ведёт свои полифонические модуляторы, а плагин не объявляет модуляцию по нотам. Отправка потребует учитывать, что одна нота звучит в нескольких генераторах сразу.
- D-061 [принято] — Значение по умолчанию, которое видит хост, — значение параметра при загрузке, а не из описания модуля. Плагин хранит копию модели на момент загрузки. Причина: `clap-validator` требует совпадения со значением после запуска, а главное, сброс ручки в DAW должен возвращать пресет: `gain` в пресете по умолчанию равен 0, сброс на 1 из описания сломал бы огибающую (D-043). Автоматизация значение по умолчанию не двигает, новое состояние и пресет меняют, поэтому при их загрузке всегда идёт `RESCAN_INFO`. Цена: значения по умолчанию после открытия проекта равны сохранённым.
- D-062 [принято] — На время `process` включены FTZ и DAZ: субнормальные числа считаются нулём, прежний режим возвращается в конце. Причина: состояние фильтра застревало на субнормальном значении, пока голос звучал с заглушённым входом (`clap-validator`, 50 109 сэмплов из 51 200 в тесте), на таких числах процессор работает во много раз медленнее. Код собран в `tools/scopedFlushToZero.h`, на процессорах без SSE, то есть на ARM (D-012), класс пока ничего не делает.

- D-063 [принято] — Два уровня графа в редакторе: холст показывает один граф, двойной клик по генератору открывает его подграф, сверху хлебные крошки `Main › Generator 1`. Причина: один код холста на оба уровня, схема с несколькими генераторами остаётся читаемой (ТЗ §8.3). Цена: оба уровня сразу не видны, маршрут модуляции между уровнями (глобальный LFO → параметр голоса) линией не дотянуть, он показывается меткой на параметре и в матрице. Отвергнуто: раскрытие генератора на месте (нужны масштаб и прокрутка холста уже при двух генераторах), две панели (каждому графу половина высоты окна).
- D-064 [принято] — Параметры редактируются ручками прямо на блоках, элементы строятся автоматически по описанию модуля (ТЗ §12). Провод модуляции тянется на ручку цели. Причина: при настройке звука под рукой сразу несколько модулей, переключаться между ними не нужно. Цена: блоки крупнее, холст заполняется быстрее, нужно окно больше прототипа. Отвергнуто: компактные блоки и боковая панель свойств, видны параметры только одного модуля.
- D-065 [принято] — Положение блока хранится в пресете, это уточняет D-020. Поле модели `position`, команда `SetModulePosition` (D-030), в файле необязательное поле модуля, поэтому версия формата осталась 1, а старые файлы получают авторасстановку. Положение есть и у заглушки D-021: её можно передвинуть, остальные данные не меняются. У макросов положения нет. План от положения не зависит, поэтому перетаскивание блока не трогает звук. Причина: разложенная вручную схема — часть пресета, иначе она терялась бы при сохранении. Цена: два одинаково звучащих пресета могут различаться как файлы. Отвергнуто: только в состоянии проекта, как было в D-020.
- D-066 [предложено] — Подписи ступеней: поле `choices` описания параметра (`Saw`, `1/4T`, `On`). Текст видят и UI, и хост, `parseParameter` принимает подпись без учёта регистра и прежние числа. В пресетах и слотах значения остаются числами, поэтому формат не меняется. Причина: хост и редактор показывали номер вместо типа волны.
- D-067 [предложено] — Правки редактора идут через `my_plug_apply_command`, единственный путь изменения модели со стороны плагина (D-030). Перед правкой забираются значения от хоста: иначе значение, ещё идущее к модели, досталось бы новому параметру, занявшему освободившийся слот. Параметр идёт в движок и хосту, остальное ещё синхронизирует таблицу слотов и сообщает хосту `clear` и `rescan`, если таблица изменилась. Хост принимает события только в `process` и `flush`, поэтому значения и начало и конец движения ручки ждут их в `SlotOutbox`: это `SlotInbox` в обратную сторону, с ячейкой на слот, без очереди и её переполнения. Начало движения, пришедшее раньше отправки конца прошлого, отменяет этот конец: для хоста это одно движение. Редактор узнаёт об изменениях по счётчику `modelRevision`, а читает модель на том же главном потоке (D-015). Каждая успешная правка вызывает `mark_dirty`, иначе DAW не предложит сохранить проект.
- D-068 [предложено] — Устройство редактора.
  - `EditorView` строит элементы по модели и переводит мышь в команды, собственного состояния схемы у него нет (ТЗ §8.2). Команда меняет модель, вид догоняет её в `update` по `modelRevision`, откуда бы правка ни пришла: от редактора, автоматизации или нового проекта. Как компонент, который рендерит store. Структура сравнивается строкой-ключом: при её изменении элементы строятся заново, значения, глубины и положения меняются на месте, поэтому ручка не пересоздаётся под мышью.
  - С плагином редактор говорит только через интерфейс `EditorBackend` (D-015). Окна и OpenGL `EditorView` не знает: тесты запускают настоящий RmlUi и настоящий плагин с пустой отрисовкой и водят настоящей мышью.
  - Положения блоков без `position` считает авторасстановка `computeLayout`: колонка по самому длинному пути от источника, выход последний, модуляторы рядом снизу. Перед первым перемещением или добавлением блока положения всего графа записываются в модель, иначе остальные блоки прыгали бы при изменении схемы.
  - Управление: перетаскивание ручки вертикально (220 точек на шкалу, Shift в 10 раз точнее), колесо (ступенчатая ровно на ступень), двойной клик сбрасывает на значение загрузки (D-061), правый клик открывает ввод числом. Правый клик по холсту открывает меню модулей. Холст двигается перетаскиванием фона и колесом, масштаба нет. Клик по проводу выделяет его и показывает кнопку удаления, Delete делает то же, если клавиатура у плагина.
  - Клавиатуру редактор забирает у DAW только для ввода текста, иначе перестали бы работать пробел и другие клавиши хоста. Поэтому удаление провода не зависит от клавиатуры. Цена: после ввода текста фокус остаётся у плагина, пока пользователь не кликнет по окну хоста.
  - Допустимые цели провода подсвечиваются теми же проверками, что у команд (`checkConnection`, `checkRoute`), поэтому недопустимый провод нельзя отпустить. Провод можно отпустить и на блок, если подходящий порт у него один.
  - Маршрут, источник которого не лежит на показанном холсте (макрос, другой уровень, velocity), виден оранжевой меткой на ручке и в матрице (D-063). Красная метка — параметру не хватило слота (D-011). Кольцо вокруг ручки показывает границы модуляции по глубинам маршрутов, а не живое значение: снимка из аудиопотока нет.
  - Макросы лежат в отдельной панели, выходы модуляции генератора внутри него показаны рядом с хлебными крошками. Матрица всегда видна внизу, маршрут между уровнями добавляется из её меню.
  - Save обновляет файл загруженного пресета, Save as создаёт новый и не заменяет существующий (ТЗ §9.2, §9.3). Смена пресета в списке отбрасывает несохранённые правки без вопроса.
  - Подписи интерфейса английские, как имена параметров (D-057). Тексты ошибок приходят из модели и пока русские.
- D-069 [предложено] — Окно. pugl и RmlUi перенесены из прототипа в основную сборку, `sint_gui_view` без окна и `sint_gui_window` с ним. Плагин для офлайн-рендера и тестов собирается с заглушкой `plugin/noEditor.cpp`, поэтому им не нужны X11 и OpenGL. Перерисовка только при изменениях: в простое 0 кадров. Размер окна меняется (минимум 800×520), масштаб приходит через `set_scale` и задаётся в единицах `dp`. На Linux события окна идут только через таймер хоста, поэтому без `clap.timer-support` окно не создаётся. На Windows при его отсутствии работает таймер pugl, это ещё не проверялось. Шрифт Noto Sans с кириллицей встроен в бинарник, закреплён по коммиту и SHA256. RmlUi читает числа в стилях через `strtof` по локали процесса, а её мог поменять хост (D-025): при десятичной запятой `0.45` стало бы нулём. Поэтому в тексте стилей нет дробных чисел, а прозрачность отключённого блока задаётся из кода. Подпись глубины форматируется `std::to_chars`, он от локали не зависит. `std::format` использовать нельзя: сборке на Fedora 44 он требует `GLIBCXX_3.4.36`, которого нет в среде flatpak-Reaper, и плагин там не загружается (D-019).

## Известные проблемы существующего кода

- Живые ноты в Reaper иногда молчат, причина не найдена. 31 октября 6 прогонов подряд на сборках без логов дали 0 на индикаторе живой ноты при остановленном транспорте, а в тех же прогонах ReaSynth звучал и айтем SIN-T при воспроизведении звучал. Сборки с логами в том же промежутке звучали. Потом та же установленная сборка звучала во всех 10 прогонах. Не влияют: тип сборки, `reaper.ini`, размер блока 128–2048, второй клиент с блоком 256. Во время молчания у пользователя шёл звонок (клиент `WEBRTC VoiceEngine`), после него плагин заработал и в обычном запуске Reaper. Связь совпадает по времени, но не доказана: имитация клиента через `pw-cat` молчание не вернула, а ReaSynth во время звонка звучал. Если повторится: сразу снимать события и `activate`/`reset`/`start_processing` записью в отображаемую в память область, без системных вызовов в аудиопотоке.
- Рендер Reaper отличается от `sint_render` с тем же пресетом примерно на 0,0075 при пике 0,37. Разница растёт со временем, как очень медленный уход фазы. Причина не найдена. Проверено, что дело не в размере блока (`sint_render` совпадает побитно при всех размерах), не в положении ноты на сетке 32 и не в громкости (лучший множитель 0,99986, остаток тот же). Начало ноты совпадает с точностью ~1e-6.
- Громкость: пик одной ноты при полной velocity ~0,09 (−21 дБ), заметно тише ReaSynth (0,39 при velocity 100). Причина не разбиралась.
- Изменение размера окна в Reaper: внешнее окно уменьшили снаружи через `XResizeWindow` до 1000×700, плагин остался 1200×780 и обрезался, `set_size` хост не вызвал. Мышью не проверялось, поэтому неизвестно, поведение ли это Reaper или особенность проверки. Если подтвердится, плагину нужен свой уголок изменения размера и `clap_host_gui.request_resize`.
- Память: каждое открытие окна оставляет ~46 КБ. Источник не наш код: без OpenGL рост 4 КБ за 100 открытий, голый pugl с OpenGL 4 КБ за 120, а пара pugl и `RenderInterface_GL3` из RmlUi 46 КБ на окно. Значит, это бэкенд RmlUi или драйвер Mesa, дальше не разбиралось. Первое окно ~75 МБ, каждое следующее ~8 МБ.
- Reaper 7.83 игнорирует `clap_host_params.clear` (D-011). Проверено зондом 31 октября: после скрытия параметра и `clear(CLAP_PARAM_CLEAR_ALL)` огибающая осталась в проекте со всеми точками (`<PARMENV 9:9 ...>`), `GetFXEnvelope` её просто не видит, пока параметр скрыт. Автоматизация привязана к номеру слота, поэтому слот, отданный новому параметру, молча получит чужую старую автоматизацию. Сейчас слоты выдаются как записано в D-011, первый свободный, и `clear` вызывается. Пользователь решил разобрать это позже. Предложенный выход: выдавать слоты по кольцу, как автоинкремент, тогда освобождённый номер вернётся не раньше чем через ~1024 выдачи. В других хостах `clear` не проверялся.

## Детали, отложенные до соответствующего этапа

- Этап 7, не проверено: скрытые параметры в FL Studio (D-011), замер памяти внутри DAW.
- После этапа 7: своя кривая на каждую стадию ENV показывается тремя ручками, график огибающей можно добавить вместо них. Живое значение модуляции на ручке требует снимка из аудиопотока. Отмена действий (D-030). Масштаб холста. Тексты ошибок модели на английском, если интерфейс останется английским (D-068).
- Этап 8: на Windows пути и имена пресетов с кириллицей: `std::filesystem::path` из `char*` читается там в кодировке системы, а CLAP передаёт UTF-8. Диапазоны параметров генератора (`polyphony` 1..64, `pitchBendRange` 0..48) предварительные, уточнить при профилировании. Релизная сборка в среде со старой glibc и со статическим `libstdc++` (D-019). С JSON плагину нужны `GLIBC_2.38` (`__isoc23_strtoll`) и `GLIBCXX_3.4.31`: в flatpak-Reaper (glibc 2.42) он загружается, на системах старше — нет. `.clap` в сборке `RelWithDebInfo` весит 34 МБ из-за отладочной информации нашего кода и статического RmlUi: в релизе её убрать. К релизу приложить лицензии встроенных зависимостей: Noto Sans (OFL), FreeType, RmlUi, pugl.

## Планы после MVP

- Источник модуляции, зависящий от аудио (D-009): модуль с выходами модуляции и с аудио сразу пока не поддержан, его параметры считались бы дважды за шаг.
- Модуль Feedback: линия задержки фиксированной длины, через которую разрешены петли в аудиографе (см. D-007).

- Устранение щелчков при модуляции типа волны, если они окажутся заметны.
- MPE и note expressions (D-027), unison (D-029), реализация undo/redo (D-030).
- `clap.preset-discovery-factory`, если подтвердится, что Reaper или FL Studio ею пользуются (D-059). `CLAP_EVENT_NOTE_END` (D-060).
- Решение проблемы переполнения пула слотов (см. D-011): например, ручное управление слотами или расширение пула с перезапуском.
